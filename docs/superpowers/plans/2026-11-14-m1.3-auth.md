# M1.3 Authentication, Roles & App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Secure role-based authentication (3-step registration, login by email or mobile, email verification, password reset, admin verification of donors) inside the mobile-first LifeLine app shell.

**Architecture:** Plain Laravel 12 controllers and Blade views on the existing `lifeline/` app. Laravel built-ins only: `Auth`, `MustVerifyEmail`, the password broker, `RateLimiter`, `signed` and `throttle` middleware. One small `role` middleware gates routes by `users.role`. Bootstrap 5 and Bootstrap Icons are served from `public/vendor/` (no CDN, no build step), and the brand lives in one plain CSS file.

**Tech Stack:** PHP 8.2 (XAMPP), Laravel 12.72, MariaDB 10.4 (XAMPP), Blade, Bootstrap 5.3.3, Bootstrap Icons 1.11.3, PHPUnit 11.

## Global Constraints

- Keep the code simple: no new Composer or npm packages (no Breeze, Fortify, Sanctum, Livewire). No JavaScript beyond `bootstrap.bundle.min.js`, except one inline `confirm()`.
- No Vite and no `@vite`: views link `public/vendor/bootstrap/…`, `public/vendor/bootstrap-icons/…` and `public/css/lifeline.css` with `asset()` (DEC-001, DEC-013).
- Roles: `donor`, `requester`, `admin`. Registration accepts only `donor` or `requester`; `users.role` is not fillable and is set explicitly.
- Mobile numbers are stored as `09XXXXXXXXX` and normalized by `App\Support\MobileNumber::normalize()` before validation, saving, and login.
- Passwords: `Password::defaults()` = at least 8 characters with letters and numbers; stored hashed (the model's `hashed` cast).
- Login: one field accepts email or mobile number; the same error message for an unknown account and a wrong password; locked after 5 failed attempts per login + IP for 60 seconds; session regenerated on login.
- Email verification is required for every app page (`verified` middleware). Donors also need admin verification (`donors.verification_status`), which affects matching and the map (M2), not login.
- No government ID upload (DEC-009). Donor eligibility rules (age, weight, donation interval) are NOT enforced at registration: they need a cited source (DEC-008) and belong to M2.3. Registration checks sanity only.
- Medical disclaimer wording (DEC-007): "LifeLine only suggests potential donors. Final compatibility and eligibility are confirmed by healthcare professionals."
- Bottom navigation tab route names (contract for M2): `home`, `map`, `requests.create`, `alerts.index`, `profile.show`. A tab is shown only when its route exists (`Route::has`), so there are no placeholder screens.
- Every form has `@csrf`. Views never use `{!! !!}`.
- Brand: red `#d32f2f` (hover `#b71c1c`), green for success; white cards on `#f6f6f8`.
- Work on branch `feat/m1.3-auth`. All commands run from `D:\ITE-18_LifeLine` unless a step says `lifeline/`. Shell commands are written for Git Bash.
- XAMPP MySQL must be running before `php artisan test`. Tests use the `lifeline_test` database (already configured in `phpunit.xml`).
- Local mail uses `MAIL_MAILER=log`: verification and reset links appear in `lifeline/storage/logs/laravel.log`.

```php
<?php

namespace App\Support;

/**
 * Philippine mobile numbers are stored in one format: 09XXXXXXXXX (11 digits).
 * The UNIQUE index on users.mobile_number only catches exact matches, so every
 * number is normalized before validation, saving and login.
 */
class MobileNumber
{
    public static function normalize(?string $number): ?string
    {
        $digits = preg_replace('/[\s\-().]/', '', (string) $number);

        if (preg_match('/^(?:\+?63|0)?(9\d{9})$/', $digits, $match)) {
            return '0'.$match[1];
        }

        return null;
    }
}
```

`lifeline/app/Http/Controllers/Auth/LoginController.php`:

```php
<?php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use App\Support\MobileNumber;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\RateLimiter;
use Illuminate\Support\Str;
use Illuminate\Validation\ValidationException;
use Illuminate\View\View;

/** Design B4: one form for every role, by email or mobile number. */
class LoginController extends Controller
{
    private const MAX_ATTEMPTS = 5;

    public function create(): View
    {
        return view('auth.login');
    }

    public function store(Request $request): RedirectResponse
    {
        $request->validate([
            'login' => ['required', 'string', 'max:255'],
            'password' => ['required', 'string'],
        ]);

        $login = trim($request->input('login'));
        $credentials = str_contains($login, '@')
            ? ['email' => $login]
            : ['mobile_number' => MobileNumber::normalize($login) ?? $login];

        // Keyed on the normalized login, so "+63…" and "09…" share one counter.
        $throttleKey = Str::lower((string) current($credentials)).'|'.$request->ip();

        if (RateLimiter::tooManyAttempts($throttleKey, self::MAX_ATTEMPTS)) {
            $seconds = RateLimiter::availableIn($throttleKey);

            throw ValidationException::withMessages([
                'login' => "Too many login attempts. Try again in {$seconds} seconds.",
            ]);
        }

        if (! Auth::attempt($credentials + ['password' => $request->input('password')])) {
            RateLimiter::hit($throttleKey);

            // Same message for unknown accounts and wrong passwords: no account enumeration.
            throw ValidationException::withMessages([
                'login' => 'These credentials do not match our records.',
            ]);
        }

        RateLimiter::clear($throttleKey);
        $request->session()->regenerate();

        return redirect()->intended(route('home'));
    }

    public function destroy(Request $request): RedirectResponse
    {
        Auth::logout();
        $request->session()->invalidate();
        $request->session()->regenerateToken();

        return redirect()->route('login')->with('status', 'You have been logged out.');
    }
}
```

```php
<?php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use App\Models\Donor;
use App\Models\User;
use App\Support\MobileNumber;
use Illuminate\Auth\Events\Registered;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Auth;
use Illuminate\Support\Facades\DB;
use Illuminate\Support\Facades\Validator;
use Illuminate\Support\Str;
use Illuminate\Validation\Rule;
use Illuminate\Validation\Rules\Password;
use Illuminate\View\View;

/**
 * 3-step registration (design B1-B3). Each step is a normal form; answers are kept
 * in the session under "registration" until step 3 creates the account.
 * Requesters skip step 2 because medical info is for donors only.
 */
class RegisterController extends Controller
{
    // Never 'admin': administrators are created by the seeder (and later by another admin).
    private const ROLES = ['donor', 'requester'];

    private const MESSAGES = [
        'mobile_number.regex' => 'Enter a Philippine mobile number, for example 0917 123 4567.',
    ];

    public function showStep1(Request $request): View
    {
        return view('auth.register.step1', ['data' => $request->session()->get('registration', [])]);
    }

    public function storeStep1(Request $request): RedirectResponse
    {
        $request->merge([
            'email' => Str::lower(trim((string) $request->input('email'))),
            'mobile_number' => MobileNumber::normalize($request->input('mobile_number')) ?? $request->input('mobile_number'),
        ]);

        $data = $request->validate($this->step1Rules(), self::MESSAGES);

        // Replaces earlier answers, so changing the role starts the later steps over.
        $request->session()->put('registration', $data);

        return redirect()->route($data['role'] === 'donor' ? 'register.step2' : 'register.step3');
    }

    public function showStep2(Request $request): View|RedirectResponse
    {
        $registration = $request->session()->get('registration', []);

        if (($registration['role'] ?? null) !== 'donor') {
            return redirect()->route('register.step1');
        }

        return view('auth.register.step2', ['data' => $registration, 'bloodTypes' => Donor::BLOOD_TYPES]);
    }

    public function storeStep2(Request $request): RedirectResponse
    {
        $registration = $request->session()->get('registration', []);

        if (($registration['role'] ?? null) !== 'donor') {
            return redirect()->route('register.step1');
        }

        $data = $request->validate([
            'blood_type' => ['required', Rule::in(Donor::BLOOD_TYPES)],
            // Sanity checks only. Eligibility rules (age, weight) need a cited source (DEC-008) and belong to matching (M2.3).
            'birthdate' => ['required', 'date', 'before:today', 'after:1900-01-01'],
            'weight_kg' => ['required', 'numeric', 'min:1', 'max:300'],
            'city' => ['required', 'string', 'max:100'],
        ]);

        $request->session()->put('registration', array_merge($registration, $data));

        return redirect()->route('register.step3');
    }

    public function showStep3(Request $request): View|RedirectResponse
    {
        if ($redirect = $this->redirectIfIncomplete($request)) {
            return $redirect;
        }

        return view('auth.register.step3', ['data' => $request->session()->get('registration')]);
    }

    public function store(Request $request): RedirectResponse
    {
        if ($redirect = $this->redirectIfIncomplete($request)) {
            return $redirect;
        }

        $registration = $request->session()->get('registration');

        $account = $request->validate([
            'password' => ['required', 'confirmed', Password::defaults()],
            'privacy_consent' => ['accepted'],
            'terms' => ['accepted'],
            'location_sharing' => ['nullable', 'boolean'],
        ]);

        // Someone may have taken the email or mobile number since step 1.
        $recheck = Validator::make($registration, $this->step1Rules(), self::MESSAGES);
        if ($recheck->fails()) {
            return redirect()->route('register.step1')->withErrors($recheck);
        }

        $user = DB::transaction(function () use ($registration, $account, $request) {
            $user = new User([
                'first_name' => $registration['first_name'],
                'last_name' => $registration['last_name'],
                'email' => $registration['email'],
                'mobile_number' => $registration['mobile_number'],
                'password' => $account['password'],
            ]);
            $user->role = $registration['role']; // set explicitly: role is not fillable
            $user->save();

            if ($user->role === 'donor') {
                // verification_status defaults to 'pending' until an admin reviews the donor.
                $user->donor()->create([
                    'blood_type' => $registration['blood_type'],
                    'birthdate' => $registration['birthdate'],
                    'weight_kg' => $registration['weight_kg'],
                    'city' => $registration['city'],
                    'location_sharing' => $request->boolean('location_sharing'),
                ]);
            }

            return $user;
        });

        $request->session()->forget('registration');
        event(new Registered($user)); // sends the verification email
        Auth::login($user);
        $request->session()->regenerate();

        return redirect()->route('verification.notice');
    }

    private function redirectIfIncomplete(Request $request): ?RedirectResponse
    {
        $registration = $request->session()->get('registration', []);

        if (! isset($registration['role'])) {
```

```php
<?php

namespace App\Http\Controllers\Auth;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Auth\Events\PasswordReset;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Password;
use Illuminate\Support\Str;
use Illuminate\Validation\Rules\Password as PasswordRule;
use Illuminate\View\View;

/** Laravel's built-in password broker (tokens in password_reset_tokens, valid 60 minutes). */
class PasswordResetController extends Controller
{
    public function create(): View
    {
        return view('auth.forgot-password');
    }

    public function store(Request $request): RedirectResponse
    {
        $request->validate(['email' => ['required', 'email']]);

        Password::sendResetLink($request->only('email'));

        // Same answer whether or not the account exists: no account enumeration.
        return back()->with('status', 'If an account uses that email address, we sent it a password reset link.');
    }

    public function edit(Request $request, string $token): View
    {
        return view('auth.reset-password', ['token' => $token, 'email' => $request->query('email')]);
    }

    public function update(Request $request): RedirectResponse
    {
        $request->validate([
            'token' => ['required'],
            'email' => ['required', 'email'],
            'password' => ['required', 'confirmed', PasswordRule::defaults()],
        ]);

        $status = Password::reset(
            $request->only('email', 'password', 'password_confirmation', 'token'),
            function (User $user, string $password) {
                // The model's "hashed" cast hashes the password; a new remember token logs out other devices.
                $user->forceFill(['password' => $password, 'remember_token' => Str::random(60)])->save();
                event(new PasswordReset($user));
            }
        );

        if ($status !== Password::PASSWORD_RESET) {
            return back()->withInput($request->only('email'))
                ->withErrors(['email' => 'This password reset link is invalid or has expired.']);
        }

        return redirect()->route('login')->with('status', 'Your password has been reset. You can now log in.');
    }
}
```

```php
<?php

namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

/** Route gate by users.role, e.g. ->middleware('role:admin') or 'role:donor,requester'. */
class EnsureUserHasRole
{
    public function handle(Request $request, Closure $next, string ...$roles): Response
    {
        abort_unless($request->user() && in_array($request->user()->role, $roles, true), 403);

        return $next($request);
    }
}
```

```php
<?php

namespace App\Http\Controllers\Admin;

use App\Http\Controllers\Controller;
use App\Models\Donor;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\View\View;

/** Admins review every new donor (no ID upload, DEC-009). Only verified donors are matched (M2.3). */
class DonorVerificationController extends Controller
{
    public function index(): View
    {
        $donors = Donor::with('user')
            ->where('verification_status', 'pending')
            ->oldest()
            ->paginate(20);

        return view('admin.donors.pending', ['donors' => $donors]);
    }

    public function verify(Request $request, Donor $donor): RedirectResponse
    {
        return $this->review($request, $donor, 'verified');
    }

    public function reject(Request $request, Donor $donor): RedirectResponse
    {
        return $this->review($request, $donor, 'rejected');
    }

    private function review(Request $request, Donor $donor, string $status): RedirectResponse
    {
        // Not fillable, so set explicitly. verified_by/verified_at record who reviewed and when, for both outcomes.
        $donor->forceFill([
            'verification_status' => $status,
            'verified_by' => $request->user()->id,
            'verified_at' => now(),
        ])->save();

        return back()->with('status', "{$donor->user->first_name} {$donor->user->last_name} is now {$status}.");
    }
}
```
