# M2.1 Donor Management & Availability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Donors keep their profile, medical info, availability, location-sharing choice, and donation history up to date. Turning availability or location sharing off takes them out of donor searches (matching in M2.3, map in M2.4).

**Architecture:** Plain Laravel 12 controllers and Blade views on the existing `lifeline/` app, built on M1.3's app shell. Three small controllers (`ProfileController`, `DonationController`, `AvailabilityController`), one query scope (`Donor::searchable()`) that M2.3 and M2.4 must use, and one migration that records registration consent times. No new packages and no JavaScript beyond one inline `confirm()`.

**Tech Stack:** PHP 8.2 (XAMPP), Laravel 12.72, MariaDB 10.4 (XAMPP), Blade, Bootstrap 5.3.3 and Bootstrap Icons 1.11.3 (vendored, DEC-013), PHPUnit 11.

**Approved at kickoff (2026-11-14):**
- Email is **not** editable in the profile (there is no re-verification flow). Name and mobile number are editable.
- If a donor changes their blood type after an admin verified or rejected them, they go back to `pending`, because matching depends on it.
- Location capture (browser geolocation and stored approximate coordinates) waits for M2.4. M2.1 only has the location-sharing toggle. Turning sharing off clears any stored approximate coordinates.
- Out of scope: change password (reset exists), account deletion (M2.6), notification preferences (M2.5), eligibility and "next eligible date" (M2.3, needs a cited interval per DEC-008).

## Global Constraints

- Keep the code simple: no new Composer or npm packages, no Vite, no `@vite` (DEC-001, DEC-013). The only JavaScript besides `bootstrap.bundle.min.js` is one inline `onsubmit="return confirm(...)"` on the delete-donation form.
- Profile, availability and donation routes act only on the signed-in user (`$request->user()`). No URL carries a donor or user id. A donation id in a URL is looked up through `$donor->donations()`, so other donors' records return 404.
- `users.role`, `users.privacy_consent_at`, `users.terms_accepted_at`, and the donor verification fields (`verification_status`, `verified_by`, `verified_at`) are never mass-assigned from request data.
- Mobile numbers are normalized with `App\Support\MobileNumber::normalize()` before validation and stored as `09XXXXXXXXX`.
- Blood types: `Donor::BLOOD_TYPES`. Store birthdate, not age (age = `$donor->birthdate->age`).
- "Last donation" is `MAX(donations.donated_on)`. There is no column for it (3NF, see `docs/database/erd.md`).
- Medical disclaimer wording (DEC-007): "LifeLine only suggests potential donors. Final compatibility and eligibility are confirmed by healthcare professionals."
- The design's "Lives Saved" stat is shown as **Completed donations** (it is not verifiable).
- Every form has `@csrf`; PATCH/PUT/DELETE forms also use `@method`. Views never use `{!! !!}`.
- Layout sections: `title`, `content`, optional `container_class`. Flash messages: `session('status')` (success), `session('error')` (danger). Field errors inline with `@error`.
- Bottom-nav route names: `home`, `map`, `requests.create`, `alerts.index`, `profile.show`. This milestone creates `profile.show`, so the Profile tab appears.
- Work on branch `feat/m2.1-donors`. Commands run from `D:\ITE-18_LifeLine` unless a step says `lifeline/`. Shell commands are written for Git Bash.
- XAMPP MySQL must be running before `php artisan test` (tests use `lifeline_test`, set in `phpunit.xml`). Never run `php artisan config:cache`.
- Commit after each task. End every commit message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

    /** Last donation = MAX(donations.donated_on); it is not stored on donors (3NF). */
    public function lastDonationOn(): ?Carbon
    {
        $date = $this->donations()->max('donated_on');

        return $date ? Carbon::parse($date) : null;
    }

    /**
     * Donors that matching (M2.3) and the map (M2.4) may show: verified by an admin,

            ->where('is_available', true)
            ->where('location_sharing', true);
    }

<?php

namespace App\Http\Controllers;

use App\Models\Donor;
use App\Support\MobileNumber;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Arr;
use Illuminate\Support\Facades\DB;
use Illuminate\Validation\Rule;
use Illuminate\View\View;

/** Design E1 "My profile" for donors and requesters. Acts only on the signed-in user. */
class ProfileController extends Controller
{
    private const MESSAGES = [
        'mobile_number.regex' => 'Enter a Philippine mobile number, for example 0917 123 4567.',
    ];

    // show() from Task 2 stays here unchanged.

    public function edit(Request $request): View
    {
        return view('profile.edit', [
            'user' => $request->user(),
            'donor' => $request->user()->donor,
            'bloodTypes' => Donor::BLOOD_TYPES,
        ]);
    }

    public function update(Request $request): RedirectResponse
    {
        $user = $request->user();
        $donor = $user->donor;

        // Only strings are normalized; anything else is left for validation to reject.
        if (is_string($request->input('mobile_number'))) {
            $request->merge(['mobile_number' => MobileNumber::normalize($request->input('mobile_number')) ?? $request->input('mobile_number')]);
        }

        // Email is not editable here (no re-verification flow). Role and verification are never taken from input.
        $rules = [
            'first_name' => ['required', 'string', 'max:100'],
            'last_name' => ['required', 'string', 'max:100'],
            'mobile_number' => ['required', 'string', 'regex:/^09\d{9}$/', Rule::unique('users', 'mobile_number')->ignore($user->id)],
        ];

        if ($donor) {
            $rules += [
                'blood_type' => ['required', Rule::in(Donor::BLOOD_TYPES)],
                // Sanity checks only, as at registration. Eligibility rules belong to matching (M2.3, DEC-008).
                'birthdate' => ['required', 'date', 'before:today', 'after:1900-01-01'],
                'weight_kg' => ['required', 'numeric', 'min:1', 'max:300'],
                'city' => ['required', 'string', 'max:100'],
                'location_sharing' => ['nullable', 'boolean'],
            ];
        }

        $data = $request->validate($rules, self::MESSAGES);

        // Matching relies on blood type, so an admin reviews a changed one again.
        $needsReview = $donor
            && $donor->blood_type !== $data['blood_type']
            && $donor->verification_status !== 'pending';

        DB::transaction(function () use ($user, $donor, $data, $request, $needsReview) {
            $user->update(Arr::only($data, ['first_name', 'last_name', 'mobile_number']));

            if (! $donor) {
                return;
            }

            $donor->fill(Arr::only($data, ['blood_type', 'birthdate', 'weight_kg', 'city']));
            $donor->location_sharing = $request->boolean('location_sharing');

            if (! $donor->location_sharing) {
                // Do not keep a location the donor no longer shares (Data Privacy Act: data minimization).
                $donor->approx_latitude = null;
                $donor->approx_longitude = null;
            }

            if ($needsReview) {
                $donor->verification_status = 'pending';
                $donor->verified_by = null;
                $donor->verified_at = null;
            }

            $donor->save();
        });

        return redirect()->route('profile.show')->with('status', $needsReview
            ? 'Your profile was updated. Because your blood type changed, an administrator will verify your donor account again.'
            : 'Your profile was updated.');
    }
}

<?php

namespace App\Http\Controllers;

use App\Models\Hospital;
use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;
use Illuminate\Validation\Rule;
use Illuminate\View\View;

/** A donor's own donation history. Donors may add and remove self-reported records only. */
class DonationController extends Controller
{
    public function index(Request $request): View
    {
        $donor = $request->user()->donor()->firstOrFail();

        return view('donations.index', [
            'donations' => $donor->donations()->with('hospital')->orderByDesc('donated_on')->get(),
            'hospitals' => Hospital::orderBy('name')->get(['id', 'name']),
            'birthdate' => $donor->birthdate,
        ]);
    }

    public function store(Request $request): RedirectResponse
    {
        $donor = $request->user()->donor()->firstOrFail();

        $data = $request->validate([
            'donated_on' => [
                'required',
                'date_format:Y-m-d',
                'before_or_equal:today',
                'after:'.$donor->birthdate->toDateString(),
                Rule::unique('donations')->where('donor_id', $donor->id),
            ],
            'hospital_id' => ['nullable', 'integer', 'exists:hospitals,id'],
        ], [
            'donated_on.after' => 'The donation date must be after your birthdate.',
            'donated_on.unique' => 'You already recorded a donation on this date.',
        ]);

        $donor->donations()->create($data + ['is_self_reported' => true]);

        return redirect()->route('donations.index')->with('status', 'Donation added to your history.');
    }

    public function destroy(Request $request, int $donation): RedirectResponse
    {
        $donor = $request->user()->donor()->firstOrFail();

        // Looked up through the donor's own records, so other donors' ids give 404.
        $record = $donor->donations()->findOrFail($donation);

        // Donations recorded through a LifeLine request (M2.3) are part of the request's history.
        abort_unless($record->is_self_reported, 403);

        $record->delete();

        return redirect()->route('donations.index')->with('status', 'Donation removed from your history.');
    }
}

<?php

namespace App\Http\Controllers;

use Illuminate\Http\RedirectResponse;
use Illuminate\Http\Request;

/** The donor's "available to donate" switch (design C1 home and E1 profile). */
class AvailabilityController extends Controller
{
    public function __invoke(Request $request): RedirectResponse
    {
        $request->validate(['is_available' => ['required', 'boolean']]);

        $donor = $request->user()->donor()->firstOrFail();
        $donor->update(['is_available' => $request->boolean('is_available')]);

        return back()->with('status', $donor->is_available
            ? 'You are now available to donate.'
            : 'You are now unavailable and will not appear in donor searches.');
    }
}
